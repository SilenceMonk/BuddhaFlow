# BuddhaFlow - 心流番茄钟

一个创新的番茄钟应用，专注于顺应自然的心流状态，而非强制中断。

## 核心理念

传统番茄钟使用倒计时（如25分钟），会强制中断可能持续更长时间的专注状态。BuddhaFlow采用**正向计时**，让你在心流中保持专注，自然地积累休息时间。

## 核心特性

### 1. 正向计时专注
- 不限制专注时长，让心流自然延续
- 实时显示当前专注时间
- 可随时暂停或结束当前专注会话

### 2. 疲劳累积模型
- **核心概念**：跟踪有效专注时间 `t_eff`（代表累积的疲劳度）
- **休息需求计算**：`rest_required = 3 + 0.004 × t_eff²`
- **疲劳累积**：每次专注后，`t_eff` 累加专注时间
- **疲劳消除**：休息后根据实际休息时间反推新的 `t_eff`

#### 具体示例
| t_eff | 休息需求 | 有效休息率 |
|-------|---------|-----------|
| 30分钟 | 6.6分钟 | 22% |
| 60分钟 | 17.4分钟 | 29% |
| 90分钟 | 35.4分钟 | 39% |
| 120分钟 | 60.6分钟 | 50.5% |

#### 休息机制
- 休息需求 ≥ 5分钟才能开始休息
- 休息时消除疲劳：
  - 剩余需求 = 原需求 - 实际休息时间
  - 如果剩余 ≤ 3分钟：`t_eff = 0`（疲劳清零）
  - 否则：`t_eff = sqrt((剩余 - 3) / 0.004)`（保留部分疲劳）
- 休息结束自动开始专注

### 3. 科学的疲劳模型优势
- **真实反映疲劳累积**：用 `t_eff` 跟踪累积疲劳，而非简单的时间累加
- **休息消除疲劳**：充分休息可以清零疲劳，重新开始
- **部分恢复机制**：休息不足时保留疲劳，提醒继续休息
- **平方增长特性**：疲劳越高，需要的休息时间呈平方级增长
- **跨会话累积**：多次专注会话的疲劳会累积，鼓励定期休息

### 4. 数据可视化

#### 过去7天趋势图
- 柱状图显示每天的总专注时间
- 帮助跟踪近期专注习惯

#### 24小时效率热力图
- 可视化展示一天中不同时段的专注表现
- 热力图颜色越深 = 该时段专注时间越长
- 帮助找出最高效的时段

## 使用方法

### 开始使用

1. 在浏览器中打开 `index.html`
2. 点击"开始专注"按钮进入专注模式
3. 专注时间会正向计时，同时累积休息时间

### 专注阶段

- 当前会话专注时间实时显示
- 休息时间基于平方模型实时累积
- 有效休息率随专注时间动态增长
- 可随时暂停或重置

### 休息阶段

- 累积休息时间≥5分钟时，"开始休息"按钮激活
- 点击开始休息，计时器切换为休息模式
- 休息时间会逐渐消耗累积的休息额度
- 可随时结束休息，继续专注

### 数据统计

- 实时查看今日和本周总专注时间
- 查看过去7天的专注趋势
- 分析24小时效率分布，找出最佳时段

## 技术实现

- 纯前端单页应用（HTML + CSS + JavaScript）

- 无需服务器，可离线使用

## 疲劳累积模型算法

### 核心状态变量

- **t_eff**（有效专注时间）：累积的疲劳度，单位：分钟
- **rest_required**（休息需求）：根据 t_eff 计算的需要休息时间

### 完整工作流程

| 阶段 | 动作 | 公式/逻辑 |
|------|------|-----------|
| **启动** | 开始一天的工作 | `t_eff = 0` |
| **专注** | 专注 `t_focus` 分钟 | `t_eff = t_eff + t_focus` |
| **计算** | 专注结束，计算该休息多久 | `rest_required = 3 + 0.004 × t_eff²` |
| **决策** | 判断是否能休息 | 如果 `rest_required >= 5`，则可以休息 |
| **休息** | 实际休息 `t_rest_actual` 分钟 | 1. `rest_remaining = rest_required - t_rest_actual`<br>2. **IF** `rest_remaining <= 3` **THEN** `t_eff = 0`<br>&nbsp;&nbsp;&nbsp;**ELSE** `t_eff = sqrt((rest_remaining - 3) / 0.004)` |

### 计算示例

#### 示例1：完整休息清零疲劳

```javascript
1. 专注30分钟：t_eff = 0 + 30 = 30分钟
2. 计算休息需求：rest = 3 + 0.004 × 30² = 6.6分钟
3. 实际休息10分钟
4. 剩余需求：6.6 - 10 = -3.4分钟 <= 3
5. 结果：t_eff = 0（疲劳清零）
```

#### 示例2：休息不足保留疲劳

```javascript
1. 专注60分钟：t_eff = 0 + 60 = 60分钟
2. 计算休息需求：rest = 3 + 0.004 × 60² = 17.4分钟
3. 实际休息10分钟
4. 剩余需求：17.4 - 10 = 7.4分钟 > 3
5. 反推：t_eff = sqrt((7.4 - 3) / 0.004) = sqrt(1100) ≈ 33.2分钟
6. 结果：保留33.2分钟的疲劳
```

#### 示例3：多次专注累积

```javascript
1. 第一次专注30分钟：t_eff = 30
   休息需求：6.6分钟，充分休息后 t_eff = 0

2. 第二次专注40分钟：t_eff = 0 + 40 = 40
   休息需求：9.4分钟，只休息5分钟
   剩余：9.4 - 5 = 4.4分钟 > 3
   反推：t_eff = sqrt((4.4 - 3) / 0.004) ≈ 18.7分钟

3. 第三次专注20分钟：t_eff = 18.7 + 20 = 38.7
   休息需求：3 + 0.004 × 38.7² ≈ 9分钟
```

### 关键公式

```javascript
// 正向计算：从 t_eff 计算休息需求
rest_required = 3 + 0.004 × t_eff²

// 反向计算：从剩余休息需求计算 t_eff
if (rest_remaining <= 3) {
    t_eff = 0  // 疲劳清零
} else {
    t_eff = sqrt((rest_remaining - 3) / 0.004)
}

// 计算还需专注多久达到目标休息需求
target_t_eff = sqrt((target_rest - 3) / 0.004)
focus_needed = target_t_eff - current_t_eff
```

## 设计哲学

**顺应自然节奏**：不强制打断心流，而是让专注和休息自然过渡。

**疲劳累积模型**：
- 用 `t_eff` 跟踪累积疲劳，而非简单计时
- 休息可以真正消除疲劳（充分休息则清零）
- 休息不足时保留部分疲劳，更符合真实体验
- 公式 `rest = 3 + 0.004 × t_eff²` 反映疲劳的非线性增长

**智能休息管理**：
- 基础休息（3分钟）确保短时专注也能恢复
- 休息需求随疲劳平方增长，反映加速累积特性
- 自动开始专注，无缝衔接工作流

**数据驱动优化**：通过可视化历史数据，帮助找出最高效的工作时段。

**真实工作场景**：支持多次短时专注累积疲劳，鼓励定期充分休息。
